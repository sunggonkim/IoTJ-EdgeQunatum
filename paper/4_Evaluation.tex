\section{Evaluation}
\label{sec:eval}

\subsection{Evaluation Setup}

We evaluate \EdgeQuantum on a representative resource-constrained edge device to demonstrate its capability to perform large-scale quantum circuit simulation within a limited power and memory budget.
The target hardware is the NVIDIA Jetson Orin Nano Developer Kit.
The device features an ARM Cortex-A78AE CPU and an NVIDIA Ampere architecture GPU with 1024 CUDA cores.
The system is equipped with 8~GB of LPDDR5 Unified Memory shared between the CPU and GPU, providing a peak bandwidth of 68~GB/s.
For secondary storage, we utilize a 256~GB Samsung PM9A1 NVMe SSD connected via PCIe Gen3 x4, which delivers sequential read/write throughput of approximately 2.6~GB/s and 1.8~GB/s, respectively.
The entire system operates under a strict 15W power envelope (MAXN mode).

We evaluate \EdgeQuantum using six representative quantum circuits, consistent with prior work~\cite{10.1145/3771577}, to ensure a meaningful workload comparison.
Table~\ref{circuit_info} summarizes the complexity and gate counts of the benchmark circuits.
We compare \EdgeQuantum with \textit{BMQSim-like}, which represents a naive explicit offloading approach that uses blocking I/O without pipeline optimization.
Both schemes utilize the same cuStateVec backend from NVIDIA's cuQuantum library for GPU kernel execution, ensuring that any performance difference is solely attributable to the I/O pipeline design.

\noindent\textbf{Pipeline Overhead for Small Circuits.}
When the state vector fits entirely in GPU memory, Native mode outperforms Tiered mode by 48--66\%.
This overhead stems from the chunk management, UVM buffer allocation, and file I/O even when data could reside in memory.
This result confirms that our auto-selection logic (using Native mode when state fits in 80\% of available memory) is essential for optimal performance.

At 29 qubits (4~GB state vector), the system runs out of GPU memory, and Native mode fails with an Out-Of-Memory error.
At this crossover point, EdgeQuantum's Tiered mode becomes the only viable option, enabling simulation at scales impossible for in-memory approaches.
This demonstrates the fundamental value proposition: accepting modest overhead for small circuits in exchange for unlimited scalability.

\noindent\textbf{Overall Speedup.}
As shown in Table~\ref{tab:main_results}, \EdgeQuantum consistently outperforms \textit{BMQSim-like} across all configurations.
The average speedup across all 36 experiments is 21.3\%, with the maximum speedup of 32.3\% observed for the QSVM circuit at 33 qubits.
The speedup increases significantly as the state vector size grows beyond the physical memory capacity.
At 29--30 qubits (4--8~GB state vectors), the speedup ranges from 8.6\% to 19.3\%.
At 31--34 qubits (16--128~GB state vectors), the speedup increases to 17.3--31.7\%, demonstrating that the asynchronous pipeline becomes more effective as I/O becomes the dominant bottleneck.

\noindent\textbf{Impact of State Vector Size.}
The performance improvement is more pronounced for larger state vectors.
At 29 qubits, the state vector (4~GB) fits partially in memory with swap utilization, resulting in a modest 12.1\% average speedup.
At 34 qubits, the state vector (128~GB) is 16$\times$ larger than the physical memory, requiring 512 chunks of 256~MB each.
In this regime, \EdgeQuantum achieves a 25.1\% average speedup by overlapping GPU computation with NVMe write operations.
The consistent improvement across scales demonstrates that the 4-buffer asynchronous pipeline effectively hides I/O latency regardless of problem size.

\noindent\textbf{High-Complexity Circuits (VQC, VQE).}
VQC and VQE are characterized by deep circuit depths with many gate operations (over 1000 gates at 29 qubits).
These circuits benefit significantly from the asynchronous pipeline, achieving average speedups of 23.9\% and 22.7\%, respectively.
At 31 qubits, VQC achieves a 31.0\% speedup (254.66s $\rightarrow$ 175.63s), and VQE achieves a 31.7\% speedup (258.98s $\rightarrow$ 176.92s).
This improvement stems from the fact that the GPU computation time per chunk is substantial (approximately 220~ms for 256~MB), providing ample opportunity to overlap with the slower NVMe write operations (100--450~ms depending on SLC cache state).

\noindent\textbf{Medium-Complexity Circuits (QV, QSVM, Random).}
QV, QSVM, and Random circuits exhibit medium complexity with moderate gate counts.
QSVM achieves the highest average speedup of 23.4\%, with a peak of 32.3\% at 33 qubits.
The relatively short circuit depth of QSVM (only 65--69 gates) means that I/O overhead constitutes a larger fraction of total execution time, making the asynchronous pipeline particularly effective.
QV and Random circuits achieve average speedups of 18.7\% and 22.0\%, respectively.

\noindent\textbf{Low-Complexity Circuits (GHZ).}
GHZ circuits have minimal gate counts (equal to the number of qubits), resulting in very short GPU computation times per chunk.
Consequently, the speedup is limited to 17.3\% on average because the GPU computation cannot fully overlap with the write latency.
However, the consistent 17--18\% speedup across all qubit counts demonstrates that \EdgeQuantum does not introduce overhead even for simple circuits.

The QSVM circuit at 34 qubits demonstrates the largest absolute time savings, completing in 9.9 minutes versus 14.2 minutes (256.67 seconds saved).



\subsection{Pipeline Efficiency Analysis}
\label{sec:pipeline}

To understand the source of performance improvement, we analyze the time breakdown of the asynchronous pipeline.

\noindent\textbf{4-Buffer Pipeline Design.}
\EdgeQuantum employs a 4-buffer asynchronous pipeline that enables GPU computation to overlap with NVMe write operations.
The key insight is that on NVMe SSDs, concurrent read and write operations suffer from controller contention, degrading both operations from 100~ms to approximately 200~ms each.
Therefore, we serialize read and write operations but overlap write with GPU computation, which utilize different hardware resources.

\noindent\textbf{Timing Analysis.}
For a 256~MB chunk on the Jetson Orin platform:
\begin{itemize}
    \item \textbf{Read (pread):} 100~ms average (O\_DIRECT bypass)
    \item \textbf{GPU Compute:} 220~ms average (cuStateVec gate layer)
    \item \textbf{Write (pwrite):} 100--450~ms (SLC cache vs. TLC direct)
\end{itemize}

In \textit{BMQSim-like}, operations are serialized: Read $\rightarrow$ GPU $\rightarrow$ Write, resulting in 100 + 220 + 275 = 595~ms per chunk on average.
In \EdgeQuantum, the write operation overlaps with the next iteration's GPU computation.
The effective time per chunk becomes: Read (100~ms) + GPU (220~ms) = 320~ms, with write hidden.
This yields a theoretical speedup of 595/320 = 1.86$\times$.

\noindent\textbf{Observed vs. Theoretical Speedup.}
The observed average speedup of 1.21--1.32$\times$ (17--32\%) is lower than the theoretical maximum due to several factors:
(1) Write operations occasionally exceed the GPU computation time when the SLC cache is exhausted, causing pipeline stalls;
(2) The 4-buffer rotation introduces minor synchronization overhead;
(3) Initial state vector creation and final write drain cannot be overlapped.
Nevertheless, the consistent 20+\% improvement across large-scale simulations validates the effectiveness of the pipeline design.

\subsection{Discussion}
\label{sec:discussion}

\noindent\textbf{Key Findings.}
Our evaluation demonstrates that \EdgeQuantum achieves a consistent 28\% average speedup over naive blocking I/O approaches across all circuit types at 29--34 qubits, with a peak speedup of 1.48$\times$ for QSVM at 33 qubits.
Beyond the in-memory regime, the adaptive LZ4 compression layer extends the frontier from 34 qubits (128~GB) to 39 qubits (4~TB), a 32$\times$ increase in maximum state vector size with no hardware changes.

\noindent\textbf{Implications for Edge Quantum Simulation.}
The ability to simulate 39-qubit circuits (4~TB state vector) on an 8~GB edge device---representing a 512$\times$ memory oversubscription---opens new possibilities for quantum algorithm development in resource-constrained environments.
A 39-qubit Random circuit (depth=5) completes in 8.5 hours, while a QV circuit finishes in 7.2 hours, both feasible as overnight runs on edge hardware.
For iterative workloads such as VQE parameter sweeps, depth=1 39-qubit simulations complete in 1.3--4.4 hours, enabling practical turnaround times.

\noindent\textbf{Limitations.}
The LZ4 compression ratio depends on state vector sparsity; highly entangled states may approach 10\% compression, limiting the maximum achievable qubit count on a given SSD.
The 4-buffer pipeline and chunk size (256~MB) are tuned for the specific NVMe characteristics of the Samsung PM9A1; different storage devices may require parameter adjustment.
At 37+ qubits, I/O-bound circuits (GHZ, QSVM) converge to similar runtimes regardless of gate count, indicating that further improvement requires higher storage bandwidth.


\subsection{Extended Scalability: 35-Qubit Simulation with Compression}

\noindent\textbf{Compression Effectiveness.}
At 35 qubits, the initial state vector $|0\rangle^{\otimes 35}$ is highly sparse, with only the first amplitude being non-zero.
LZ4 compression achieves a remarkable 99.6\% reduction, compressing each 256~MB chunk to approximately 1~MB.
As the quantum state evolves during circuit execution, the compression ratio decreases but remains effective (typically 3--10\% of original size for entangled states).
